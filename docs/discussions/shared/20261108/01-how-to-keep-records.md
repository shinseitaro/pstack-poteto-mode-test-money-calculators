# 2026-11-08 議論の記録の残し方

## 背景

loan-simulator のブランドづくりを始めるにあたり、ユーザーから
「議論は今後の資料になるので、共通の履歴として残したい。どういう方法がいいか」と相談があった。

## Claude の提案

**このリポジトリの中に Markdown で残し、git で履歴を管理する。**

- 新しいセッションの Claude は前の会話を覚えていない。リポジトリにあれば、毎回読み直して続きから始められる。
- いつ・何を・なぜ変えたかが commit に残る。GitHub でも読める。
- 調査側の `app-store-optimization-explorer` も `docs/` と `HANDOFF.md` で管理しているので、やり方がそろう。

置き方：

| 何を | どこに | 書き換えるか |
|---|---|---|
| 議論の記録（提案・判断・選ばなかった案・未決） | `docs/discussions/YYYY-MM-DD-<テーマ>.md`（下の「ユーザーの修正」で変更） | 書き換えない（時系列で積み上げる） |
| 決めたこと（今の結論） | 各製品のディレクトリ、`README.md` | いつも最新に書き換える。議論の記録へリンクする |
| 次のセッションへの案内と、記録のルール | `CLAUDE.md` | 必要に応じて |

## 選ばなかった方法

| 方法 | 選ばなかった理由 |
|---|---|
| Claude の memory 機能 | 短い事実を覚えるためのもの。中身がユーザーから見えにくく、議論の記録には向かない |
| Claude Docs（claude.ai の文書） | コメントで話し合うには便利だが、git の外にあり、読むたびに外部のツールを通すことになる |
| 会話をそのまま保存（`/export`） | ツールの出力なども混ざり、あとから読む資料としては読みにくい。原本を取っておく補助としてはあり |
| リポジトリ直下の `shared/` に置く（README の当初の構成） | 議論の記録は `docs/discussions/` にまとめて置く方が探しやすい |

## ユーザーの判断

「その形で進めてください」。上の提案のとおりに決定。

## ユーザーの修正：ファイルの置き方

最初は `docs/discussions/2026-11-08-loan-simulator-target.md` のように、日付とテーマを1つのファイル名に入れていた。
ユーザーから「`docs/discussions/loan-simulator/20261108/01-xxxxxx.md` の方がスッキリ」と指摘があり、次の形に変えた。

```
docs/discussions/<対象>/<YYYYMMDD>/<NN>-<テーマ>.md
```

- `<対象>`：`loan-simulator`・`pro-financial-calc`・`shared`
- `<NN>`：その日・その対象の中での順番

`shared` は Claude が足したもの。A・B に共通のことや、この記録のようにリポジトリ全体に関わることを置く。
