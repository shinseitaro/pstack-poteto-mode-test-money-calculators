# 2026-11-08 loan-simulator の機能と画面の構成

## 背景

ターゲットと伝えることを決めたあと（[`loan-simulator/target-and-message.md`](../../../../loan-simulator/target-and-message.md)）、
ユーザーから「今までの結果で、私達のアプリの機能リストを考え、画面構成を考えたらどうでしょう？」。

ブランドより先に、何を作るかを形にする。紹介ページで何を見せるかも、ここから決まる。

根拠：

- 決めたこと：主役は家を買う人とローンを返している人。芯は「信頼できる」。
  一番の約束は「最初から広告が無く、あとからも足さない」。二番目の約束は「開いてすぐ計算できて、要るときだけ詳しく」。
- 使ってみた5つのアプリ（[08](08-hands-on-summary.md)）：
  - 単純なアプリ（[05](05-hands-on-loan-deposit-tool.md)、入力4つ）も、細かいアプリ（[04](04-hands-on-karls-mortgage.md) Karl's）も、200万以上インストールされている。
  - 日付つきの返済スケジュールと「何か月目から」の追加返済は Karl's だけ。ただし使いにくい。

## Claude の提案（たたき台）

### 1. 機能リスト

#### 最初の版（v1）に入れる

| | 機能 | 中身 | どの約束・根拠 |
|---|---|---|---|
| 1 | すぐ計算 | 借りる額・金利・期間の3つで、月々の支払いと利息の合計。前回の値を覚えておく | 二番目の約束「開いてすぐ」 |
| 2 | 1回目の内訳 | 1回目の支払いのうち、利息がいくらで元金がいくらか（$30万・3.5%・30年なら $1,347.13 のうち利息 $875、元金 $472.13） | 「数字の理由が見える」 |
| 3 | 家の費用 | 物件価格と頭金（% か $）、固定資産税、火災保険、PMI、HOA。月々の合計を内訳つきで出す。開くまで隠しておく | 家を買う人に要るもの（[01](01-target-and-message.md)） |
| 4 | 返済スケジュール | 日付つき。月ごと・年ごとの切り替え。残高のグラフ。今日の行に印をつける | 返している人に要るもの。Karl's だけが持つ（[04](04-hands-on-karls-mortgage.md)） |
| 5 | 追加返済 | 毎月・毎年・1回だけを、「何か月目から」で組み合わせる。隔週払い（年26回）も選べる。早く終わる月数と、減る利息を出す | 同上。$200/月の追加で73か月早く、利息が約 $42,090 減る |
| 6 | ローンの保存 | 名前をつけて保存。開始日から「今日の残高」「あと何回」を出す | 「契約前に比べる → 返しながら見直す」の流れ |
| 7 | 比べる | 2〜3つの条件（30年と15年、銀行Aと銀行B など）を並べる。月々・利息の合計・終わる日・差額 | 家を買う人が銀行の提案を比べる場面 |
| 8 | 集めない | アカウントなし、広告用の ID なし、統計の送信なし。データは端末の中だけ | 一番の約束を支える根拠 |

#### あとの版で考える

| 機能 | 理由 |
|---|---|
| 車のローン（下取り・消費税・隔週） | 脇役のターゲット。既存のアプリ（[06](06-hands-on-car-loan.md)）が十分強く、v1 で差がつきにくい |
| 借り換えの比較（今のローンの残り vs 新しいローン＋諸費用） | 返している人に価値が高い。ただし入力が増えるので、v1 を出してから |
| 変動金利（ARM） | 米国では固定が主流。計算と画面が複雑になる |
| スケジュールの書き出し（PDF・CSV）、画像で共有 | 家族や担当者と話すときに便利。v1 の核ではない |

#### やらないこと

| やらないこと | 理由 |
|---|---|
| 広告 | 一番の約束 |
| 金利の紹介、銀行・ローン会社への案内 | 既存のアプリの稼ぎ方。「ほかの誰かの商売で邪魔しない」に反する |
| 複利・積立 | A から外すと決めた |
| アカウント、クラウド同期 | 集めない約束。バックアップは OS の仕組みと書き出しで足りる |

### 2. 画面の構成

**考え方**：開くとすぐ計算の画面。説明の画面、同意の画面、広告の待ち時間は出さない。
詳しい項目は、同じ画面の中で「開くと出てくる」ようにして、画面の数を増やさない。

画面は5つ。下のタブは2つ（計算・保存したローン）にして、迷わせない。

```
[計算]  ←→  [保存したローン]          右上：設定
   │              │
   ├ 返済スケジュール   └ 比べる
   └ 追加返済（下から出るシート）
```

#### ① 計算（開いたときの画面）

```
┌──────────────────────────┐
│ Loan amount   $300,000   │
│ Rate             3.5 %   │
│ Term          30 years   │
├──────────────────────────┤
│  $1,347.13 / month       │  ← 大きく
│  Total interest $184,968 │
│  1st payment: $875 interest│
│              $472 principal│
├──────────────────────────┤
│ ▸ Home costs (tax, PMI…) │  ← 開くと 3. の項目
│ ▸ Extra payments         │  ← 開くと ③
│ ▸ Start date             │
├──────────────────────────┤
│ [Schedule]  [Save]       │
└──────────────────────────┘
```

- 何も開かなければ、入力3つの単純な計算機（[05](05-hands-on-loan-deposit-tool.md) と同じくらい単純）。
- 「Home costs」を開くと、月々の合計が「元金と利息＋税金＋保険＋PMI＋HOA」に変わる。

#### ② 返済スケジュール

- 日付・支払い・元金・利息・残高の表。月ごと・年ごとの切り替え。
- 上に残高のグラフ。追加返済があれば「追加返済なし」の線と並べる。
- 保存したローンなら、今日の行に印。

#### ③ 追加返済（下から出るシート）

- 「毎月 $200、2027年1月から」のような行を足していく。隔週払いの切り替えもここ。
- 下に結果：「2050年10月に終わる（6年1か月早い）」「利息が $42,090 減る」（$30万・3.5%・30年、1回目が2026年12月、毎月 $200 を1回目から）。

#### ④ 保存したローン

- カードの一覧：名前、今日の残高、終わる日、月々の支払い。
- タップすると①に読み込む。2〜3つ選んで「比べる」。

#### ⑤ 比べる

- 選んだローンを横に並べた表。月々・利息の合計・終わる日・総支払額と、一番安いものとの差。

#### 設定

- 通貨と表示、データの書き出し・読み込み、購入と復元。
- 「このアプリが集めないもの」のページ（広告用の ID、統計、アカウント）。紹介ページでもそのまま使える。

## まだ決めていないこと

1. **v1 の範囲**：上の「v1 に入れる」8つでよいか。特に「比べる」と「家の費用」を v1 に入れるか。
2. **車のローン**：Claude の提案は「あとの版」。脇役のターゲットを v1 で拾うかどうか。
3. **最初に出すのは iOS か Android か**：米国が先なら iOS の利用者が多い。調査のレビューも iOS が中心。
   ただし今日触ったのは Android だけで、iOS の既存アプリは未確認（HANDOFF 4.1）。
4. **無料で使える範囲**：値段と売り方を決めるときに一緒に決める。例：①は無料、②〜⑤は買い切りで開く。

## ユーザーの判断

ユーザーの答え：「1,2 OK 3. Android から 4. まずは全部無料でいいのではと思います」。

1. **v1 の範囲**：提案の8つで決定。
2. **車のローン**：あとの版。提案のとおり。
3. **最初に出すのは Android**。今日 Android の既存アプリを触り、adb で操作して確かめるやり方もできている。
4. **最初は全部無料**（ユーザーの考え）。

Claude からの注意（4. について）：

- 無料にすると、まず使ってもらいやすい。需要を確かめる段階に合っている。
- ただし、あとから有料に変えると、既存の利用者には「あとから悪くした」と見える
  （調査の低評価レビューの17%が「更新で悪くなった」）。一番の約束「あとからも足さない」とぶつかる。
- 有料にするときは、それまでの利用者が使えていた機能を取り上げない形にする必要がある。
  値段と売り方は、出す前にあらためて決める。
