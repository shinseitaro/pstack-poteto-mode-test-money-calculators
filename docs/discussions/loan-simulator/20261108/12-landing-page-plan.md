# 2026-11-08 loan-simulator の紹介ページ：先に出して要望を集める

## 背景

名前を LoanChart に決めたあと（[11](11-brand-foundation.md)）、ユーザーから：

> ドメイン取る前に紹介ページを作って先にユーザのニーズや要望を集めるというのはどうでしょう？よく https://wayk.io このようなイチペラのサイトを見かけます。これを netlify などで作って上げておいて、今作っているところだけど要望があったら教えてほしい、という自由に書込ができる場所、もしくは、アンケート場所など作っておいてマーケティングしたらどうでしょう？

README の「次にやること」の3（紹介ページで、興味を示す人がいるか確かめる）を、前に進める提案。

## Claude の考え

賛成。理由：

- お金をかけずに、アプリを作る前に「欲しい人がいるか」「何が欲しいか」を確かめられる。
- Netlify の無料の住所（例：`loanchart.netlify.app`）で始めれば、ドメインは反応を見てから決められる。
- Stitch で作った画面を、そのまま「こんなアプリです」の絵に使える。

気をつけること：

1. **紹介ページ自身が約束を守る**。「集めない」と言うアプリの紹介ページに、Google Analytics や広告のタグを入れると矛盾する。
   計測のタグは入れない。数えるのは、フォームに書き込まれた数だけにする。メールアドレスは任意にして、何に使うかを書く。
2. **置くだけでは人は来ない**。紹介ページとは別に、人を呼ぶ場所が要る（例：Reddit の住宅購入・家計の掲示板。宣伝の決まりが厳しいので、各掲示板の決まりを読んでから）。これは次の議論にする。
3. **名前を公に出す前に、米国の商標を確かめる**（[brand.md](../../../../loan-simulator/brand.md) のチェックリスト）。ページを出すと名前が公になる。
4. Netlify のアカウントはユーザーのもの。公開の操作はユーザーにお願いする（または、ユーザーがログインした上で Claude が CLI で行う）。

### ページの中身（たたき台）

英語、1ページ。

1. 見出し：名前と一言。例：*LoanChart — See your whole loan. No ads. Not now, not later.*
2. 3つの特長と、Stitch の画面：
   - 開いてすぐ計算（① 計算の画面）
   - 日付つきの返済スケジュールと、追加返済の効果（② ③）
   - 広告なし・集めない（設定の「What this app doesn't collect」）
3. 「いま作っています」と正直に書く。
4. 短いアンケート（3〜4問）＋自由に書ける欄：
   - いまローンの計算に何を使っているか
   - いちばん困っていること
   - 欲しい機能（v1 の機能から選ぶ＋その他）
   - 出たら知らせてほしい人だけ、メールアドレス（任意）
5. 「このページも、何も追跡しません」の一文。

フォームは Netlify Forms を使えば、サーバーを用意しなくてよい。

## 追記：ページを作った

[`loan-simulator/landing/`](../../../../loan-simulator/landing/README.md) に作った。

- 英語の1ページ。見出し「See your whole loan.」、3つの特長（The answer first／Your loan, by date／Nothing in the way）、Stitch の画面5枚。
- アンケート：状況（家を買う・返している・車・その他）、いま何で計算しているか、v1 の機能のどれを使うか、自由に書く欄、メール（任意）。
  - 「状況」は Claude が足した。主役のターゲット（家を買う人・返している人）が本当に来るかを確かめるため。
- 計測のタグ・Cookie・外部フォントは入れていない。文字は端末の字体を使う。
- 一番下に「LoanChart is a calculator, not a lender.」。
- Chrome でパソコン幅とスマホ幅（390px）を表示して確かめた。スマホ幅で見出しの左右の余白が消えていたので直した。

注意：Netlify Forms は、迷惑な投稿を見分けるために、回答を Akismet（外部のサービス）に送って確かめる。ページの「no tracking scripts」は正しいが、「回答を誰にも渡さない」と書くなら、この点を知っておく必要がある。

## 追記：公開の前の判断

- **商標**：ユーザーが USPTO の Trademark search で「loanchart」を調べた。有効（登録・審査中）も失効も **0件**（[画面](images/uspto-loanchart.png)）。ユーザー：「OKです」。
  - 2語の「loan chart」では調べていない。気になれば、あとで調べる。
- **メールの書き方**：ユーザーが「2a」を選んだ。「we won't share it with anyone」を「We won't sell it or use it for anything else.」に変えた（回答が迷惑投稿の判定で Akismet に送られるため）。

## 追記：公開した

**https://loanchart.netlify.app** に公開した（2026-11-08）。

- Netlify の MCP でのプロジェクト作成は、429（回数の制限）で失敗した。ユーザーの端末に残っていた Netlify CLI のログインを使って、CLI で作って公開した。
- 新しいプロジェクトはフォームの検出が無効だったので、MCP で有効にして公開し直した。フォーム `needs` が認識されたことを確かめた。
- テストの回答を1件送り、届いたことを確かめてから消した。
- わかったこと：Netlify Forms は、回答と一緒に**送った人の IP アドレスとブラウザの種類**を保存する。ページの「no cookies, no analytics, no tracking scripts」は正しいが、「何も集めない」とは言えない。ページではそう言っていない。

## 追記：アンケートの動作確認

- ユーザーがパソコンの Chrome から回答を1件送った（自由に書く欄に「THIS IS TEST」、メール `test@test.com`）。
  **迷惑な投稿（Spam submissions）に振り分けられた**。ユーザーが管理画面で「Verify」を押すと、正式な回答に移り、Claude から読めた。中身を確かめて消した。
  - 振り分けの理由は、たぶん `test@test.com` と「TEST」の文字。はっきりしない。
  - **公開している間は「Spam submissions」も時々見る**（Claude の MCP からは迷惑な投稿の一覧を読めない）。
- チェックを2つ以上つけた場合を、Claude が送って確かめた。**全部の値が届いた**（例：`wants` に3つ）。確かめて消した。
- ユーザーがスマホ（Android の Chrome）から1件送った（メールなし、自由に書く欄は日本語）。**迷惑な投稿にならず、そのまま正式な回答として届いた**。確かめて消した。
  - パソコンの回答だけが迷惑な投稿になったのは、`test@test.com` と「TEST」の文字のせいだった可能性が高い。
