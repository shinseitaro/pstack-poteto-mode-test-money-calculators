# 2026-11-08 Stitch で画面を作った

## 背景

[09](09-features-and-screens.md) で v1 の機能と画面を決めたあと、ユーザーから「実物の画面を観たいので Google Stitch をつかったらどうでしょうか？」。
さらに「MCPを使う手もあるみたいです」と、Stitch の MCP を使う方法の提案。

## やったこと

1. Stitch の MCP をこのリポジトリにつないだ。
   - API キーはユーザーが発行し、`.env` に置いた（`.gitignore` 済み）。`.mcp.json` には `${STITCH_API_KEY}` だけを書いた。
   - ユーザーの判断：キーの置き場所を聞かれて「.env とかない？」。それに合わせた。
2. Claude が [stitch-prompts.md](../../../../loan-simulator/design/stitch-prompts.md) のプロンプトで7画面を作った。1画面目で Stitch が作った見た目（深い緑青色、Roboto Flex）を、残りの6画面にも使った。
3. 画像を見て、指示と違う所を直させた。
4. 画像を [`loan-simulator/design/stitch/`](../../../../loan-simulator/design/stitch/README.md) に置いた。

## 確かめたこと

- **数字はすべて計算どおり**（月 $1,347.13、1回目の利息 $875.00、追加返済で2050年10月・$42,090 減、比べる画面の差額など）。Stitch は数字を変えなかった。
- **アプリ名・広告・ログインは、どの画面にも出なかった**。

直させた所（Stitch が指示にないものを足した、または重複させた）：

| 画面 | 何があったか | 直した結果 |
|---|---|---|
| ② 返済スケジュール | Balance 列が無い。v1 に無い「Export full schedule」ボタン。「3 rows」の表示 | ボタンと表示は消えた。Balance 列は足されたが、**右にはみ出す**（下の「わかったこと」1） |
| ③ 追加返済 | ボタンが「+ + Add」と＋が二重 | 直った |
| ④ 保存したローン | 「294 payments left」が2回。銀行のカードで月々の支払いが2回 | 直った |
| ⑤ 比べる | 下の注記が不正確（「equal principal and interest payments…」） | 「Principal and interest only. Taxes, insurance and PMI are not included.」に変えた |
| 設定 | 一番下に「Calm Financial Architecture / Exact arithmetic」。デザインの仕組みの名前が漏れたもの。「正確」は売りにしないと決めた言葉 | 消した |

## わかったこと（Claude の考え）

1. **返済スケジュールの表は、スマホの幅に5列（日付・支払い・元金・利息・残高）が入らない**。
   案：支払いが毎月同じなら「支払い」の列を表の上に1回だけ出し、表は4列にする。または1行を2段にする。
2. **結果が入力より上にある並び**（Stitch が選んだ）は、「開いてすぐ答えが見える」に合っていて良い。
3. **「家の費用」を開くと画面が長くなる**（①' は ① の約1.4倍の高さ）。それでも上の結果は同じ位置にあり、「要るときだけ詳しく」は形になっている。
4. 「このアプリが集めないもの」を設定に置くと、一番の約束を画面の中でも見せられる。紹介ページにもそのまま使えそう。

## 追記：表の形の決定

Claude が3つの案（4列にする／1行を2段にする／横にスクロール）を出し、ユーザーが「1.がいいと思います」。
**決定：返済スケジュールの表は4列（日付・元金・利息・残高）。月々の支払いは表の上に1回だけ出す**（「Monthly payment $1,547.13 (includes $200 extra)」）。
Stitch で作り直し、残高まで画面の幅に収まることを確かめた（[03-schedule.png](../../../../loan-simulator/design/stitch/03-schedule.png)）。
